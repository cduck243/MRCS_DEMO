## 1. 우선순위 산정

### 1.1 점수

```
우선순위 점수 = 비어 있는 금액 × 중증질환 가중 × 발생 빈도 가중
```

**왜 세 축인가** — 비어 있는 금액만으로 줄을 세우면 희귀하지만 부담이 큰 병이
앞으로 나온다. 실제로 겪을 가능성이 낮은 병을 1순위로 두면 준비 순서가 뒤틀린다.

| 축 | 값 |
|---|---|
| 비어 있는 금액 | STEP 4의 `gap` = 필요금액 − 준비금액 |
| 중증질환 가중 | 암·뇌혈관·심장·치매를 포함한 분야 **1.3** / 그 외 1.0 |
| 발생 빈도 가중 | 아래 표 |

| 대분류 환자수 | 가중 |
|---|---|
| 100만명 이상 | 1.00 |
| 30만 ~ 100만명 | 0.90 |
| 10만 ~ 30만명 | 0.80 |
| 3만 ~ 10만명 | 0.65 |
| 3만명 미만 | 0.50 |

환자수는 국민건강보험공단·건강보험심사평가원 2024년 진료 통계의 성별 환자수를 쓴다.

### 1.2 분야 좁히기 — 정신건강 질환 → 치매 질환

정신 및 행동장애는 민영보험이 대부분 보장하지 않는다.
실손은 F04~F99의 비급여를 전면 면책하고, 한국신용정보원 표준 담보코드에도
정신질환의 진단·수술·치료 담보가 없다. 담보가 있는 것은 **치매**(`A4109` 치매진단 ·
`A4110` 경증치매)뿐이다.

"무엇부터 준비할까"를 정하는 화면에서 이 분야를 통째로 올려 두면
**준비할 수 없는 것을 준비 대상으로 읽게 된다.**
그래서 STEP 5에서는 치매(`F00-F09-01`)로 좁혀 표시하고, 좁힌 이유를 카드 안에 적는다.

| 화면 | 표시 | 이유 |
|---|---|---|
| STEP 4 | 정신건강 질환 (14개 질병군 전체) | 지금 상태를 보여 주는 화면. 보장 밖도 사실이므로 그대로 둔다 |
| **STEP 5** | **치매 질환** (`F00-F09-01`) | 무엇부터 준비할지 정하는 화면. 준비할 수 있는 것만 올린다 |

설정 위치는 `build_step5.py` 의 `FIELD_NARROW` 이다.

### 1.3 대표 질병군 — STEP 4와 다르게 고른다

| 화면 | 대표 선정 기준 | 이유 |
|---|---|---|
| STEP 4 | 필요금액이 가장 큰 질병군 | 최악의 경우를 보여 주는 화면 |
| **STEP 5** | **비어 있는 금액 × 발생 빈도**가 가장 큰 질병군 | 무엇부터 준비할지 정하는 화면 |

이 차이 때문에 눈 질환의 대표가 STEP 4에서는 `시각장애 및 실명`,
STEP 5에서는 실제로 흔한 병이 된다.
두 화면의 숫자가 달라 보일 수 있으므로 화면에 기준을 명시한다.

### 1.4 산정 결과 (예시 · 남성 · 균형준비형)

| 순위 | 분야 | 대표 질병군 | 비어 있는 금액 | 비어 있는 보장 |
|---|---|---|---|---|
| 1 | 심장과 혈관 질환 | 뇌졸중 | 12,989만 | 수술 · 치료 · 입원 · 간병 |
| 2 | 치매 질환 | 치매 등 기질성 정신장애 | 14,922만 | 진단 · 치료 · 간병 |
| 3 | 사고로 인한 손상과 중독 | 두부 손상 | 14,881만 | 진단 · 치료 · 통원 · 간병 |
| 4 | 폐와 호흡기 질환 | 간질성 폐질환 | 14,355만 | 치료 · 간병 |
| 5 | 눈 질환 | 시각장애 및 실명 | 14,348만 | 치료 · 간병 |

> 암과 종양이 5위 안에 없는 것은 이 예시 보유담보에 **암 진단비 3,000만원**이
> 들어 있어 상대적으로 준비되어 있기 때문이다. 순위는 보유 담보에 따라 달라진다.

## 2. AI 분석 섹션

### 2.1 지금 구현

`aiParagraphs()` 함수가 지도의 값으로 문단 4~5개를 만든다.
문단마다 **근거 라벨**을 달아 어디에서 온 이야기인지 보이게 한다.

| 문단 | 내용 | 근거 라벨 |
|---|---|---|
| 1 | 전체 진단 — 병원비는 실손이 메우고, 비어 있는 건 끊긴 수입 | 4단계 계산 결과 · 실손 표준약관 |
| 2 | 1순위 분야와 그 이유 | 공단 2024 진료 통계 · 질병별 명세서 건수 |
| 3 | 보장 종류별 공백 (간병 · 치료) | 신용정보원 담보코드 · 노인장기요양보험 |
| 4 | 보험이 다루지 않는 영역 (있을 때만) | 실손 표준약관 면책 조항 |
| 5 | 비상자금으로 버틸 수 있는 기간 | 3단계 입력값 · 통계청 가계동향조사 |

### 2.2 로컬 모델 연결 — 구현됨

`tools/ai_brief.py` 와 `tools/serve.py` 로 실제 동작합니다.
브라우저가 모델을 직접 부르지 않고 **로컬 서버를 거칩니다.**

```
step5.html ──▶ /api/brief ──▶ ai_brief.run() ──▶ Ollama (localhost:11434)
                   │                                    │
                   │              ┌─────────────────────┘
                   │              ▼
                   │         검사기 통과?
                   │           ├ 예 → 슬롯 채우고 화면에
                   └───────────┴ 아니오 (3회) → 규칙 기반 문장 유지
```

서버를 거치는 이유 — 브라우저의 교차 출처 제한(CORS)에 걸리지 않고,
https 페이지에서 http://localhost 를 부르면 막히는 문제도 피합니다.
그리고 이 자리가 그대로 실서비스의 서버 API가 됩니다.

**숫자는 모델이 쓰지 않습니다.** 금액·개월수·%는 `{{슬롯}}` 으로 두게 하고
검사를 통과한 뒤에 우리가 채웁니다. 작은 모델이 숫자를 흘리거나 바꾸는 사고를 이렇게 막습니다.

| 슬롯 | 뜻 |
|---|---|
| `{{fieldCount}}` | 고른 질병 분야 수 |
| `{{indemRate}}` | 필요 병원비 중 실손이 메우는 비율 |
| `{{cashRate}}` | 정액이 감당해야 할 몫 중 준비된 비율 |
| `{{restMonths}}` | 1순위 분야에서 일을 쉬게 되는 기간 |
| `{{needAmount}}` · `{{emptyAmount}}` | 필요 금액 · 비어 있는 금액 |
| `{{gap1Fields}}` · `{{gap2Fields}}` | 보장이 비어 있는 분야 수 |
| `{{emergencyMonths}}` | 비상자금으로 버틸 수 있는 기간 |

단위는 슬롯 값 안에 넣습니다. 모델이 뒤에 또 붙여 `74%%`, `15,174만만` 이 되던
문제를 그렇게 없앴습니다. 채운 뒤 중복 단위를 한 번 더 정리합니다.

#### 검사기 — 통과해야만 화면에 올립니다

| 검사 | 내용 |
|---|---|
| 숫자 직접 입력 | 슬롯 밖에 숫자가 있으면 탈락 |
| 없는 슬롯 | 주어지지 않은 이름을 쓰면 탈락 |
| 슬롯 사용량 | 5개 미만이면 탈락 (사실이 빠진 밋밋한 문장 방지) |
| 금지 표현 | '치명적', '생명을 위협', 보험사 이름, 가입 권유 |
| 지시문 복붙 | '~라는 점', '~는 이유' 등 프롬프트를 그대로 옮긴 흔적 |
| 반말 | '~이다', '~한다' 로 끝나면 탈락 |
| 길이 | 문단당 165자 초과 시 탈락 |

탈락하면 사유를 붙여 최대 3회까지 다시 시킵니다. 그래도 안 되면 폴백합니다.

#### 모델 비교 (M5 Max 48GB · 2026-09-03)

| 모델 | 통과 | 시간 | 평가 |
|---|---|---|---|
| **Qwen3 8B** | 3회 | 3.9초 | **채택.** 문장이 가장 자연스럽고 사실을 빠짐없이 담습니다 |
| EXAONE 3.5 7.8B | 2회 | 2.4초 | 빠르지만 길이를 줄이라고 하면 문장을 부수고 숫자만 남깁니다 |
| gemma3 27B | 실패 | 13~20초 | 길이 제한을 못 맞추고 느립니다. 이 작업엔 과합니다 |

> 처음엔 EXAONE의 한국어가 나아 보였지만, 프롬프트를 다듬고 나니 Qwen3가 앞섰습니다.
> 작은 모델 비교는 프롬프트를 고정한 뒤에 해야 의미가 있습니다.

### 2.2b 실서비스 전환

`aiParagraphs()` 자리에 **LLM 호출**이 들어간다.
입력으로 넘길 것과 지켜야 할 선은 아래와 같다.

```
입력   조건(성별·인내수준·월지출·비상자금)
       분야별 필요금액 · 준비금액 · 비어 있는 금액 · 급부 상태
       급부별 공백 집계 · 보장 밖 목록
출력   문단 4~5개 + 각 문단의 근거 라벨

지킬 것
  · 특정 보험회사·상품을 지목하지 않는다
  · 통계에 없는 숫자를 만들지 않는다
  · 공포를 조장하지 않는다 ("치명적", "생명을 위협" 같은 표현을 쓰지 않는다)
  · 보장 밖 영역을 '부족하다'고 쓰지 않는다
  · 존댓말 · 평서문 · 친근하게
```

### 2.3 채우는 방법 세 갈래

1페이지에서 소개한 **수용 · 전가 · 회피** 관점을 그대로 잇는다.

| 갈래 | 뜻 | 수단 |
|---|---|---|
| **줄이기** | **위험 자체를 줄인다** | 국가건강검진 · 국가암검진 · 치매 조기검진 · 생활습관 |
| 감당하기 | 스스로 감당할 몫을 정한다 | 비상자금으로 버틸 개월수 · 감당할 범위 정하기 |
| 넘기기 | 남는 것을 보험으로 넘긴다 | 진단비·간병비 정액 담보 · 소득보상 담보(A9602) · 실손 세대 점검 |

**'줄이기'에서 공적 제도를 뺀 이유** — 본인부담상한제·산정특례·상병수당 같은 제도는
새로 준비할 대상이 아니라 **이미 있는 것**이다. 준비 방법 자리에 두면 할 일처럼 읽힌다.
이 자리에는 위험의 가능성과 크기를 실제로 줄이는 방법만 두고,
제도는 아래 **알아보기** 섹션으로 옮긴다.

검진 항목의 근거 —

| 항목 | 대상 · 주기 | 출처 |
|---|---|---|
| 일반건강검진 | 만 20세 이상 2년마다 (비사무직 매년) · 혈압·혈당·콜레스테롤, 만 66세부터 인지기능 | 국민건강보험공단 |
| 위암 | 40세 이상 2년 · 위내시경 | 국립암센터 국가암검진사업 |
| 대장암 | 50세 이상 1년 · 분변잠혈검사 | 〃 |
| 간암 | 40세 이상 고위험군 6개월 · 간초음파 + AFP | 〃 |

### 2.4 알아보기 — 이미 준비되어 있는 것

새로 준비할 대상이 아니라, 있는지 모르고 못 쓰는 경우가 많은 제도들이다.
대부분 **신청해야 받는** 구조라 알아 두는 것만으로 준비가 된다.
카드를 누르면 지원 수준·남는 빈틈·출처를 모달로 보여 준다.

| 제도 | 성격 |
|---|---|
| 국민건강보험 | 의료비 |
| 본인부담상한제 | 의료비 상한 |
| 산정특례 | 중증질환 의료비 |
| 재난적의료비 지원 | 과도한 의료비 |
| 노인장기요양보험 | 간병 · 돌봄 |
| 상병수당 | 쉬는 동안의 소득 |
| 고용보험 구직급여 | 쉬는 동안의 소득 |

데이터는 `lookup.items` — STEP 3의 `means.public` 6종에 구직급여를 더한 7종이다.

> **소득 단절 대비 담보** — 한국신용정보원 담보코드에
> `A9602 질병상해구직급여지원금` · `A9603 구직급여지원금` (보장유형: 비용지원)이 있다.
> 병으로 일을 못 하게 된 기간의 소득을 메우는 담보로,
> 지금 가장 크게 비어 있는 **생활비 공백을 정면으로 겨냥하는 유일한 유형**이다.
> 실제 취급 상품과 지급 요건 확인이 필요하다.

## 3. 보장리포트

### 3.1 PDF로 저장

```
window.print() + @media print
  숨김   dock · 개발 노트 · rail · 시연용 컨트롤 · 버튼
  유지   조건 · 우선순위 5장 · AI 분석 · 근거
  분할   .prio / .ai / .report 는 break-inside: avoid
```

브라우저 인쇄 대화상자에서 대상을 "PDF로 저장"으로 고르게 안내한다.

> **확정 필요** 서버 렌더링(Puppeteer 등) 방식으로 갈지, 브라우저 인쇄로 둘지.
> 서버 렌더링이면 워터마크·발행번호·발행일시를 넣을 수 있다.

### 3.2 상담사 연결 — 비대면 · 비실명

```
1단계  보낼 항목을 고른다 — 조건 · 우선순위 · 비어 있는 보장
2단계  익명 코드가 만들어지고, 상담사는 그 코드로만 상담을 연다
3단계  상담 중 언제든 중단할 수 있고 기록은 남지 않는다
4단계  이어가기로 할 때만 연락처를 받는다
```

| 리포트에 담기는 것 | 담기지 않는 것 |
|---|---|
| 성별 · 위험인내수준 · 월 지출 구간 | 이름 · 연락처 |
| 준비 상태 · 비어 있는 보장 | 주민등록번호 · 증권번호 · 주소 |

> **확정 필요** 익명 코드 발급·전달 방식, 보관 기간, 상담사 접근 권한 범위.
> 개인정보 처리방침과 함께 정해야 한다.

## 5. 서버 구조 (실서비스)

지금은 소비자 컴퓨터에서 로컬 모델이 돕니다. 실서비스에서는 **MRCS 서버가 대신** 부릅니다.

```
소비자 브라우저 ──▶ MRCS 서버 ──▶ 추론 서버 (사내 GPU)
                        │              Qwen3 8B · vLLM 또는 Ollama
                        ├──▶ 검사기
                        └──▶ 실패 시 규칙 기반 문장
```

**소비자 브라우저가 모델을 직접 부르지 않습니다.** 프롬프트와 모델이 노출되고,
호출량을 통제할 수 없기 때문입니다.

### 5.1 왜 로컬(온프레미스)인가

입력에 **건강 상태와 보유 담보가 함께** 들어갑니다.
외부 API로 보내면 개인정보 처리방침에 위탁 사실을 적고 고지해야 합니다.
사내 GPU에서 돌리면 그 문제가 생기지 않습니다.

| 방식 | 비용 | 데이터 |
|---|---|---|
| 외부 API | 호출당 종량제 | 밖으로 나감 · 위탁 고지 필요 |
| **로컬 모델** | GPU 서버 고정비 | **밖으로 나가지 않음** |
| 규칙 기반 | 0 | 밖으로 나가지 않음 |

### 5.2 규모 산정

8B 모델은 24GB GPU 한 장에 올라가고, 이 작업은 요청당 3~5초입니다.
동시 처리는 배치로 묶어 늘립니다.

| 항목 | 값 |
|---|---|
| 모델 | Qwen3 8B (4bit 양자화 시 약 6GB) |
| GPU | 24GB 한 장으로 시작 (RTX 4090 · L4 급) |
| 요청당 | 3~5초 · 입력 약 900토큰 · 출력 약 400토큰 |
| 실패율 | 재시도 3회 안에 통과 · 실패 시 폴백 |

### 5.3 반드시 둘 것

| 항목 | 이유 |
|---|---|
| **타임아웃** | 8초를 넘으면 폴백. 소비자를 기다리게 하지 않습니다 |
| **폴백** | 규칙 기반 문장이 항상 준비돼 있어야 합니다. 모델이 죽어도 화면은 돕니다 |
| **검사기** | 모델 출력은 언제나 검사를 거칩니다. 예외 없습니다 |
| **호출 제한** | 세션당 재생성 횟수 제한. 무한 호출을 막습니다 |
| **로그** | 생성된 문장과 검사 결과를 남깁니다. 나중에 프롬프트를 고칠 근거가 됩니다 |
| **프롬프트 버전** | 프롬프트를 고치면 버전을 올리고 로그에 남깁니다 |

### 5.4 로컬 실행 패키지

전달용으로 그대로 열리는 묶음을 함께 둡니다.

```
index.html          더블클릭하면 열립니다 (AI 없이도 전부 동작)
start.command       macOS — 모델 확인 후 서버 실행
tools/serve.py      정적 서버 + /api/brief
tools/ai_brief.py   프롬프트 · 검사기 · 폴백
실행방법.md          받는 사람을 위한 안내
```

`python3` 만 있으면 되고 설치할 라이브러리가 없습니다.
AI 기능은 선택 사항이라, Ollama가 없어도 화면은 정상 동작합니다.

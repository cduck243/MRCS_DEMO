# MRCS 중분류 소비자 문구 작성 지침

## 목적
생애위험준비지도(MRCS) 2페이지에서, 소비자가 "내가 걱정하는 질병"을 고르고
"그 병이 어떤 병인지" 이해하도록 돕는 설명문을 만든다.
의료 전문가가 아니라 **보험을 준비하려는 일반 소비자**가 독자다.

## 문체 규칙 (반드시 지킬 것)
1. **존댓말 + 평서문.** "~합니다", "~입니다" 로 끝낸다. "~하세요" 명령형은 whenToSee에서만.
2. **친근하게.** 딱딱한 고지문이 아니라 옆에서 설명해 주는 말투.
   - 나쁜 예: "본 질환군은 다양한 병인에 의해 발생하며 중증도에 따라 예후가 상이합니다."
   - 좋은 예: "원인이 여러 가지여서, 어떤 원인인지에 따라 치료 기간이 크게 달라집니다."
3. **한 문장에 한 가지 사실.** 문장이 길어지면 나눈다.
4. **의학용어는 풀어쓴다.** 꼭 필요하면 괄호로 원어를 병기한다.
   - "허혈성 심장질환" → "심장에 피가 잘 안 가서 생기는 병(허혈성 심장질환)"
   - "예후" → "치료 결과", "대증치료" → "증상을 가라앉히는 치료"
5. **겁주지 않는다.** MRCS의 원칙은 "위험은 무서운 것이 아니라 준비하는 것"이다.
   공포 마케팅 표현("치명적", "생명을 위협하는")은 쓰지 않는다.
   대신 사실을 담담히 쓴다("입원이 필요한 경우가 많습니다").
6. **없는 사실을 만들지 않는다.** 원본 데이터에 없는 통계·수치·확률은 절대 쓰지 않는다.
   금액이나 일수를 임의로 쓰지 않는다.
7. **보험 상품을 권유하지 않는다.** "가입하세요", "보장이 필요합니다" 같은 표현 금지.
   대신 "입원 기간이 길어질 수 있어 입원 보장을 함께 보게 됩니다" 처럼 중립적으로.

## 출력 형식
입력 파일의 `items` 배열 각 항목에 대해 아래 JSON 객체를 만든다.
**입력 항목 수와 출력 항목 수가 정확히 같아야 하고, code 값은 그대로 유지한다.**

```json
{
  "code": "A00-A09",
  "officialName": "장 감염 질환",
  "consumerName": "장염 (장 감염 질환)",
  "oneLiner": "세균이나 바이러스가 장에 들어가 염증을 일으키는 병입니다.",
  "plain": "2~3문장. 이 병이 어떤 병인지, 가볍게 지나가는 편인지 오래 가는 편인지, 소비자가 알아야 할 특징.",
  "symptoms": ["설사를 한다", "배가 아프다", "토하거나 열이 난다"],
  "causes": ["오염된 음식이나 물", "사람 간 접촉으로 옮는 감염"],
  "treatment": ["수분 보충과 증상 조절", "원인에 맞는 항생제나 항바이러스제"],
  "careFlow": ["증상과 언제부터인지 확인", "필요하면 혈액·대변 검사", "원인에 맞는 치료", "탈수가 심하면 입원"],
  "benefits": {
    "surgery":    {"level": "rare",      "note": "대개 수술은 하지 않습니다. 합병증이 생기면 시술이 필요할 수 있습니다."},
    "admission":  {"level": "sometimes", "note": "탈수가 심하거나 먹지 못하면 입원합니다."},
    "outpatient": {"level": "often",     "note": "가벼운 경우는 외래에서 치료합니다."},
    "care":       {"level": "rare",      "note": "간병이 필요한 경우는 드뭅니다."}
  },
  "whenToSee": "물도 못 마실 정도로 토하거나, 고열과 함께 처지면 바로 병원에 가세요.",
  "evidence": {
    "basis": "KCD 8차 분류 A00-A09 범위의 일반 정보를 소비자 언어로 재작성",
    "source": "KCD 분류 · 국가건강정보포털 · 임상진료지침정보센터",
    "review": "의료전문가 검수 필요"
  }
}
```

### 필드별 규칙
- `consumerName`: 소비자가 아는 이름을 앞에, 공식명을 괄호에. 소비자 이름이 따로 없으면 공식명만 쓴다.
  - 예: "장염 (장 감염 질환)", "결핵", "위·십이지장 궤양 (소화성 궤양)"
- `oneLiner`: 한 문장, 40자 내외.
- `plain`: 2~3문장. **"이 병은 어떤 성격인가"**를 알려준다. 치료가 짧게 끝나는지, 오래 가는지,
  재발이 잦은지, 후유증이 남는지 같은 **준비와 연결되는 특징**을 반드시 한 가지 포함한다.
- `symptoms` / `causes` / `treatment`: 3~4개. 소비자가 쓰는 말로.
- `careFlow`: 3~5단계. "→"로 잇지 말고 배열 원소로 나눈다.
- `benefits.level`: `often`(흔함) / `sometimes`(경우에 따라) / `rare`(드묾) / `none`(해당 없음) 중 하나.
  **입력 데이터의 src_surgery / src_admit / src_outpatient / src_care 내용을 근거로 판단한다.**
  임의로 정하지 않는다. note는 한 문장.
- `whenToSee`: "~하세요" 형태 허용. 응급 상황을 구체적으로.
- `evidence.basis`: 어떤 원본을 어떻게 재작성했는지 한 문장.

## 주의
- 산부인과(KCD15), 신생아(KCD16), 선천성(KCD17) 항목은 특히 조심스럽게 쓴다.
  불안을 키우지 말고, "대부분 잘 관리됩니다" 같은 사실적 안심 문구를 넣을 수 있으면 넣는다.
- 정신건강(KCD05) 항목은 낙인이 될 표현을 피한다. "정신병", "미친다" 같은 표현 절대 금지.
  자살·자해 관련 내용이 나오면 "혼자 견디지 말고 전문가의 도움을 받으세요"로 안내한다.
- 사고·손상(KCD19)은 질병이 아니라 사고임을 전제로 쓴다.
